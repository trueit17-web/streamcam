# streemcam

Просмотр камер (RTSP, Xiaomi, Tuya/Smart Life, Dahua) из Telegram и Discord для пользователей из белого списка.

## Быстрый старт

1. `copy config.example.yaml config.yaml`, `copy .env.example .env`, заполнить.
   Секрет: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
   Сгенерировать и вписать ещё STREEMCAM_INTERNAL_KEY (той же командой).
2. Публикация наружу — выбрать одно (`COMPOSE_PROFILES` в `.env`):
   - **VPS с белым IP** — `COMPOSE_PROFILES=caddy`, `STREEMCAM_DOMAIN=cams.example.com`;
     A-запись домена → IP сервера, порты 80/443 открыты. Caddy сам получит сертификат Let's Encrypt.
   - **Домашний сервер без белого IP** — `COMPOSE_PROFILES=cloudflared` (DNS домена должен быть в Cloudflare):
     Cloudflare Zero Trust → Networks → Tunnels → Create tunnel → токен в `CLOUDFLARE_TUNNEL_TOKEN`,
     Public hostname: `cams.example.com` → `http://streemcam:8080`.
3. `docker compose up -d --build`

## Telegram
1. @BotFather → `/newbot` → токен в `TELEGRAM_BOT_TOKEN`.
2. @BotFather → `/newapp` → выбрать бота → URL = `public_url`, short name = `mini_app_short_name`.
3. Добавить бота админом в канал, в личке боту: `/post_channel`, закрепить пост.
4. Команды: `/cams`, админам — `/allow <id|dc:id>`, `/deny`, `/users` (можно ответом на сообщение).

## Discord
1. https://discord.com/developers → New Application → Bot → токен в `DISCORD_BOT_TOKEN`.
2. OAuth2 → URL Generator: scopes `bot`, `applications.commands` → пригласить на сервер.
3. ID сервера в `discord.guild_ids` (команды появятся сразу).
4. Команды: `/cams`, админам — `/allow`, `/deny`, `/users`.

## Доступ

`/deny` отзывает доступ сразу, но пользователи из списка `allow` в config.yaml снова получат доступ после перезапуска — чтобы отозвать навсегда, удалите их и из config.yaml.

## Камеры Xiaomi
Открыть http://127.0.0.1:1984 (WebUI go2rtc, только с сервера) → Add → Xiaomi → войти в аккаунт
Mi Home. go2rtc сохранит ключ в `go2rtc/go2rtc.yaml` (streemcam его не перезаписывает).
Там же видны `did` и `model` камер. Для получения ключей go2rtc нужен интернет.
Список поддерживаемых моделей — в документации go2rtc (`internal/xiaomi`).
Xiaomi Smart Camera C701 — model chuangmi.camera.079ae2 (поддерживается go2rtc ≥ 1.9.13).

## Камеры в домах через WireGuard
Камеры Xiaomi отдают видео только в локальной сети, а Imou через облако упираются в лимиты трафика.
Поэтому сервер подключается к домашним сетям через WireGuard: на сервере работает контейнер `wireguard`,
роутеры домов подключаются к нему клиентами, и go2rtc забирает видео с камер напрямую.
1. На сервере в `.env` впишите домашние сети, они не должны совпадать:
   `WG_LAN_DOM1=192.168.1.0/24`, `WG_LAN_DOM2=192.168.2.0/24`, `WG_LAN_DOM3=192.168.3.0/24`.
   Добавьте профиль `wireguard`: `COMPOSE_PROFILES=caddy,wireguard`. Затем выполните `docker compose up -d`.
2. Откройте UDP-порт 51820 в панели провайдера VPS (облачный файрвол или security group), если он там есть.
   Файрвол самого сервера контейнер открывает сам.
3. Конфиги для роутеров лежат на сервере в `wireguard/peer_dom1/peer_dom1.conf` (и `dom2`, `dom3`).
   В них приватные ключи, поэтому не пересылайте их через чаты, а переносите с сервера сами.
   Импортируйте файл в роутер как WireGuard-клиент. Если роутер ругается на строку `DNS =`, удалите её.
4. На роутере разрешите доступ из туннеля в домашнюю сеть (в Keenetic это «Межсетевой экран» для
   подключения WireGuard; в MikroTik — правила forward; в OpenWrt — зона wg → lan).
5. Закрепите за камерами постоянные IP (резервирование DHCP) и проверьте с сервера `ping 192.168.2.10`.
   Подключение домов видно в проверке `status` в блоке «wireguard».
6. Добавьте камеры в `config.yaml` по их адресам в домашней сети. Камеры Imou понимают RTSP как Dahua
   (`type: dahua`, пользователь `admin`, пароль — код безопасности с наклейки, `subtype: 1` для записи).
   Такие камеры пишутся и смотрятся без облака Imou.

## Камеры Imou через P2P (как приложение Imou Life)
Приложение Imou Life показывает видео через P2P-облако Dahua (Easy4IP): камера сама держит связь с ним,
поэтому не нужны ни роутеры, ни проброс портов, ни трафик открытой платформы Imou. Контейнер `dhp2p`
повторяет это для сервера: по серийному номеру он открывает в docker-сети обычный RTSP камеры.
Используется экспериментальный проект [dh-p2p](https://github.com/khoanguyen-3fc/dh-p2p); не все модели
могут поддерживаться.
1. В `.env`: добавьте профиль `p2p` (`COMPOSE_PROFILES=caddy,p2p`), камеры
   `DHP2P_CAMERAS=7927BCCRSF84AE5:1601 C7AA8CEPSF70702:1602` (серийник:порт, порт — любой свободный)
   и пароли камер — код безопасности с наклейки: `IMOU_CAM1_PASSWORD=...`. Затем `docker compose up -d`.
2. Проверка `status` покажет блок «p2p»: ответ `RTSP/1.0 401 Unauthorized` значит, что туннель работает.
   Если туннель не устанавливается (Timeout), попробуйте `DHP2P_RELAY=1`.
3. Добавьте камеру в `config.yaml`:
   ```yaml
   - id: imou_dvor_p2p
     name: Двор (P2P)
     type: dahua
     host: dhp2p
     port: 1601
     user: admin
     password: ${IMOU_CAM1_PASSWORD}
   ```
   Запись идёт со второго потока (`subtype: 1`), как у остальных камер Dahua.

## Камеры Tuya / Smart Life
1. В `config.yaml`: `tuya.enabled: true`, в `.env` — `STREEMCAM_INTERNAL_KEY`.
2. В приложении Smart Life / Tuya Smart: «Я» → ⚙ → «Аккаунт и безопасность» → «Код пользователя».
3. В личке с ботом (админ): `/tuya_login <код>` → бот пришлёт QR → Smart Life → сканер → подтвердить.
4. Камеры аккаунта появятся в плеере автоматически (`/tuya_status` — список, `/tuya_logout` — выход).
Вход использует client_id интеграции Tuya из Home Assistant; если Tuya его заблокирует, вход перестанет работать.

Потоки Tuya прописываются прямо в конфиг go2rtc (`go2rtc.yaml`) и применяются через `POST /api/restart`
(go2rtc API не позволяет добавить источник `echo:`/`exec:` через `/api/streams`, только через файл конфига)
— поэтому после `/tuya_login`, `/tuya_logout` или изменения списка камер аккаунта go2rtc ненадолго
перезапускается и текущие зрители переподключаются. Поскольку `go2rtc.yaml` в результате содержит
`STREEMCAM_INTERNAL_KEY`, файл должен оставаться локальным (не публиковать), а API go2rtc — слушать
только `127.0.0.1`/сеть docker (как и задано в `docker-compose.yml`).

## Камеры Imou (облако)
Для камер Imou (например, IPC-C32EP), до которых VPS не достаёт по сети. Просмотр и запись (см. «Запись и архив»);
поток идёт через облако Imou (HLS, если недоступен — облачный RTSP), поэтому задержка — несколько секунд.
1. Зарегистрируйтесь на [open.imoulife.com](https://open.imoulife.com) тем же аккаунтом, что в приложении
   Imou Life, создайте приложение и скопируйте `appId` и `appSecret`.
2. В `.env`: `IMOU_APP_ID`, `IMOU_APP_SECRET` и `STREEMCAM_INTERNAL_KEY`; в `config.yaml`: `imou.enabled: true`.
3. После перезапуска все камеры аккаунта появятся в плеере и в `/cams` (список обновляется раз в
   `imou.refresh_minutes`). Если ключи не подошли или облако недоступно, админы получат сообщение в Telegram.

Если аккаунт зарегистрирован в другом регионе, укажите региональный адрес API в `imou.api_url`
(например, `https://openapi-fk.easy4ip.com/openapi`). Если камера видна, но поток не открывается,
выключите в Imou Life шифрование видео для этой камеры. У бесплатного тарифа разработчика есть квоты
на число запросов и трансляций, поэтому сервис бережёт запросы: список камер обновляется не чаще раза
в час (`imou.refresh_minutes` меньше 60 не действует), а адрес потока запоминается на 6 часов и
обновляется раньше, только если по нему не пошло видео. Если один аккаунт перестал отвечать
(например, исчерпал лимит, ошибка `OP1013`), камеры остальных аккаунтов остаются в списке. Потоки Imou, как и Tuya, прописываются в `go2rtc.yaml`.

Камеры чужих домов (переключатель домов в Imou Life) открытый API Imou не отдаёт. Если владелец поделится
камерой («Поделиться» в Imou Life), она появится в списке, но видео облако по вашим ключам не отдаст
(«OP1009 No right»), даже с полными правами. Для видео владелец регистрируется на open.imoulife.com,
создаёт своё приложение и даёт его ключи: они добавляются в `imou.accounts` (см. `config.example.yaml`),
секреты — в `.env` (`IMOU2_APP_ID`, `IMOU2_APP_SECRET`). Камеры этого аккаунта берутся по его ключам,
а `home` у аккаунта задаёт им дом.

## Группировка по домам
В плеере камеры сгруппированы по домам; по умолчанию дома свёрнуты и раскрываются по тапу.
Кнопка ↻ рядом с домом сразу спрашивает облака Tuya/Imou о статусе камер (не чаще раза в 30 с).
Кнопка **Live** переключает список в режим одновременного просмотра: видны только дома, а при раскрытии дома сразу запускается видео всех его онлайн-камер (не больше `max_streams_per_user`). Раскрыт один дом за раз, при открытии другого потоки прежнего останавливаются.
Офлайн-камеры не запускаются: облако и go2rtc за ними не ходят, пока статус не станет «онлайн».
- Tuya: дом берётся из Smart Life автоматически.
- Imou: `imou.home` — дом для всех камер Imou.
- Камеры из `config.yaml`: поле `home` у камеры.
- `homes` — дом для конкретной камеры по её названию или id (`tuya_…`, `imou_…`, id из конфига),
  перекрывает всё остальное. Так удобно разложить по домам расшаренные камеры Imou.

Камеры без дома попадают в группу «Другие камеры».

## Совместимый режим (H.265)
C701 отдают H.265 — его показывают Safari/iOS и Chrome/Edge с аппаратным декодированием. Если видео чёрное,
включите в плеере «Совместимый режим»: сервер перекодирует поток в H.264 720p. Одновременно — не больше
`max_transcodes` таких просмотров.

## Запись и архив
- Запись идёт по расписанию (`recording.start`–`recording.end`, часовой пояс `recording.timezone`)
  из дополнительного потока камеры (Xiaomi — `record_subtype`, по умолчанию 1), перекодируется в H.264
  и режется на часовые файлы `recordings/<камера>/<ГГГГ-ММ-ДД>/<ЧЧ-ММ-СС>.mp4`.
- Архив доступен всем из белого списка: в плеере кнопка «Архив» → камера → дата → час, есть «Скачать».
- Очистка: записи старше `retention_days` удаляются; если свободно меньше `min_free_gb`, удаляются самые старые часы.
- Оценка места: доп. поток ≈ 0,15–0,2 ГБ/ч на камеру → 3 камеры × 11 ч ≈ 5–7 ГБ в сутки.
- Imou пишутся из SD-потока облака (поток `imou_…~rec`) без перекодирования: так меньше трафика Imou
  и не грузится процессор. Если облако не отдаёт SD, пишется основной поток.
- Не писать камеру: `record: false` у камеры; не писать Tuya: `recording.tuya: false`; не писать Imou: `recording.imou: false`.
- Если запись не идёт больше `alert_minutes`, админам придёт уведомление в Telegram.

## Деплой и мониторинг (GitHub Actions)
- `deploy` — после каждого слияния в `main` (и вручную) заходит на сервер по SSH, делает
  `git merge --ff-only origin/main`, пересобирает и перезапускает контейнеры (`deploy/remote-deploy.sh`)
  и проверяет, что streemcam отвечает на `127.0.0.1:8080`.
- `status` — раз в час и вручную: контейнеры, ответ streemcam, диск, ошибки в логах (`deploy/remote-status.sh`).
  При проблеме запуск падает, и GitHub присылает письмо.

Пока секреты не заданы, оба workflow просто пропускаются. Настройка:
1. Ключ только для деплоя: `ssh-keygen -t ed25519 -N "" -f streamcam_deploy`;
   `streamcam_deploy.pub` добавить в `~/.ssh/authorized_keys` пользователя сервера, которому принадлежит
   клон и который входит в группу `docker`.
2. Клон на сервере должен уметь `git fetch origin` без пароля (публичный репозиторий или deploy key).
3. GitHub → Settings → Secrets and variables → Actions → New repository secret:
   `PROD_SSH_HOST`, `PROD_SSH_USER`, `PROD_SSH_KEY` (содержимое `streamcam_deploy`),
   `PROD_SSH_KNOWN_HOSTS` (вывод `ssh-keyscan -p <порт> <хост>`), `PROD_PATH` (путь к клону),
   при нестандартном порте — `PROD_SSH_PORT`.

## Изменение конфигурации

`go2rtc.yaml` генерируется только одноразовым сервисом `go2rtc-config` — go2rtc и streemcam
его не перечитывают сами. После правки `config.yaml`:

- Docker: `docker compose up -d --force-recreate go2rtc-config go2rtc streemcam`
- Без Docker: заново выполнить `python -m streemcam render-go2rtc`, затем перезапустить go2rtc
  и streemcam.

## Без Docker
`pip install .`, поменять адреса в конфиге (см. комментарии), затем
`python -m streemcam render-go2rtc`, запустить go2rtc с `go2rtc/go2rtc.yaml`, `python -m streemcam run`.

## Выдать ссылку вручную
`docker compose exec streemcam python -m streemcam link tg:123456 --base http://127.0.0.1:8080`
